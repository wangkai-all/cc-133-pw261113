# 供水分区（DMA）水平衡分析

导入入口表、出口表与用户总表的累计读数，按日查看输入、输出与差额；点击某天可核对参与计算的每段读数与缺测范围。纯前端页面 + 可独立测试的领域模块，无第三方依赖。

## 运行

```bash
npm start          # http://localhost:8080
npm test           # 领域规则单元测试（node:test）
```

页面上的三套样本对应需求场景：

- **样本A · 换表/回绕/人工更正**：IN-01 在 11-12 换表（事件切分新旧两段）；UM-01 回绕按模数推定；UM-03 误抄由更正事件修正；IN-02 在 11-14 出现无依据负差 → 记为**未解释**（不当回绕），当日覆盖率归零、不输出比例；UM-02 为 08:00 抄表（跨日区间按时长分摊并标记**估算**），11-14/15 缺测。
- **样本B · 反向计量**：双向边界表夜间读数下降，按反向流量计（负用量冲减输出），差额可正可负。
- **样本C · 边界调整**：BD-07 的导入配置为全期进水（过时）。在"表计与边界配置"中把它改为 11-12 起出水（先生效止=2026-11-12，再加一行 outlet 自 2026-11-12），勾选"对比修正前后"即可看到 11-12 起差额由 +200 变为 0。

## 核心规则（src/domain/）

1. **累计读数 → 区间用量**（`meters.js`）：负差不一律当回绕——
   - 有换表事件：按事件时刻切分，旧表段 = 止码 − 起读数，新表段 = 止读数 − 起码；缺止码/起码的分段记未知；
   - 有人工更正：替换/插入更正读数后按普通差计算；更正记录可直接给定区间用量（标记估算）；
   - 双向表：负差为反向计量（用量为负）；
   - 其余负差：仅当配置了回绕模数且换算结果在该表最大计量能力内，记**回绕推定**（带假设标记）；否则记**未解释**，用量为未知（不是 0）。
2. **跨日分摊**（`days.js`）：区间跨自然日时按重叠时长比例分摊，分摊部分一律标记 `estimated`，与整点实测区分；无读数覆盖的时段为**缺测**，不计 0。
3. **有效覆盖率** = 当日可确定用量的时长 / 24h（未解释与缺测都压低覆盖率）。分区日覆盖率取各表最小值（保守）。**覆盖率低于阈值（默认 0.8，可调）时不输出确定的漏损比例**，差额仍如实展示。
4. **边界表按生效日期**（`compute.js`）：绑定含角色（入口/出口/用户）与生效起止；分区关系变更后，各日按当时生效的绑定计算。差额 = 输入 − 输出，仅表示未平衡，不能直接认定漏水。
5. **导出保留过程**（`io.js`）：日汇总 CSV、区间明细 CSV（每段的换算方式/假设/是否估算，缺测与未解释各占一行）、完整 JSON（含配置快照与未解释清单）。

## CSV 格式

| 文件 | 列 |
|---|---|
| 读数（入口/出口/用户三个入口均可） | `meter_id,timestamp,value[,source]`，时间 `YYYY-MM-DD HH:MM`（本地时区） |
| 表计属性 | `meter_id,name,modulus,bidirectional,max_rate_m3h` |
| 边界绑定 | `meter_id,zone,role(inlet/outlet/user),effective_from,effective_to(可空)` |
| 事件 | `event_type(replacement/correction),meter_id,time,old_final,new_initial,corrected_value,usage_override,note` |

手工导入读数时会自动登记表计（属性默认空，可在页面修改）并按导入入口创建绑定（生效起=首日）。
